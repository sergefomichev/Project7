# BLOCK-BY-BLOCK WORKFLOW

The website is built one block at a time.

Never redesign the entire site unless explicitly requested.

Every block follows the same workflow.

---

# STEP 1 — LOAD CONTEXT
# STEP 1A — READ PROJECT RULES

Before asking questions:

Read:

- DESIGN_DIRECTION.md
- FORBIDDEN_PATTERNS.md
- BLOCK_IMPLEMENTATION_RULES.md
- CODEX_WORKFLOW.md

Summarize internally:

- design principles
- forbidden patterns
- motion principles
- composition principles

Do not ask questions until these files have been reviewed.

Before discussing the next block:

Review:

- existing website
- existing sections
- current visual language
- current motion language
- current typography system
- current layout rhythm

Identify:

- strengths
- weaknesses
- opportunities

---

# STEP 2 — DISCOVERY QUIZ

Before planning a block, run a short discovery interview.

Ask concise questions.

Do not ask more than necessary.

Always ask:

1. What is the purpose of this block?

2. Provide references for this block.

3. Are there any special instructions?

4. What content will appear inside this block?

5. Should this block be:
   - informative
   - emotional
   - conversion focused
   - storytelling focused
   - immersive

Then ask only the most useful additional questions.

Possible topics:

- content
- emotion
- interaction
- animation
- visual style
- mobile requirements

Maximum:

3 questions if references are provided.

10 questions if references are missing.

Stop questioning when enough information exists.

---

# STEP 3 — REFERENCE ANALYSIS

Analyze all provided references.

Extract:

- composition
- hierarchy
- typography
- spacing
- layering
- motion
- storytelling
- interaction patterns

Explain:

- what should be adopted
- what should be avoided
- what should be reinterpreted

Do not copy references.

---

# STEP 4 — CREATIVE DIRECTIONS

Generate 3 possible directions.

For each direction explain:

- visual identity
- composition
- typography
- motion
- emotional impact
- risks

Recommend one direction.

---

# STEP 5 — BLOCK PLAN

Create a complete plan.

Define:

- purpose
- hierarchy
- focal point
- layout
- motion
- transitions
- layering
- mobile adaptation

Do not write code.

---

# STEP 6 — DESIGN REVIEW

Review your own solution.

Check:

- originality
- emotional impact
- visual hierarchy
- memorability
- premium feel
- performance
- mobile quality

Identify weaknesses.

Improve the plan.

---

# STEP 7 — AI TEMPLATE REVIEW

Check for:

- generic SaaS layouts
- startup hero patterns
- repetitive cards
- dashboard aesthetics
- AI-generated clichés

Replace weak ideas.

---

# STEP 8 — IMPLEMENTATION PLAN

Create implementation roadmap.

Include:

- components
- files
- animations
- responsive behavior
- performance concerns

Do not write code unless implementation is requested.

---

# STEP 9 — IMPLEMENTATION

Only after approval:

Implement the block.

Follow all project rules.

Preserve consistency with previous blocks.

---

# STEP 10 — POLISH PASS

After implementation:

Improve:

- spacing
- typography
- motion
- transitions
- hover states
- responsiveness
- visual rhythm

---

# STEP 11 — CHECKPOINT

After block approval:

1. Commit changes.
2. Push to GitHub.
3. Create rollback point.
4. Deploy to Docker.
5. Verify deployment.

Only then begin work on the next block.

---

# QUALITY STANDARD

Always think like:

- Awwwards Judge
- Art Director
- Senior Product Designer
- Creative Technologist

The goal is not to create a website.

The goal is to create a memorable digital experience that feels handcrafted, premium, intentional, and impossible to mistake for a generic AI-generated template.

# BLOCK COMPLETION RULE

After a block is approved:

1. Commit changes.
2. Push to GitHub.
3. Create version tag.
4. Deploy Docker build.
5. Verify deployment.
6. Ask user:

"Are we ready to move to the next block?"

Only after confirmation begin Discovery Quiz for the next block.

Never assume the next block automatically.
